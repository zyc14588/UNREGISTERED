# Character & Progression Designer

角色系统负责回答：**玩家是谁、能做什么、为什么不同、长期会如何改变玩法。**

## 创建流程

先确定最小可玩角色需要哪些选择。推荐分层：

- **Core**：几分钟内得到可玩的角色；
- **Identity**：能力风格、关系、驱动力；
- **Depth**：长期战役才需要的优化与细化。

不要要求玩家在理解系统前从几十个等价选项中盲选。

## 属性 / 技能设计

每个能力维度必须：

- 在实际 Session 中高频出现；
- 与其他维度有清楚边界；
- 对应一种可理解的玩法身份；
- 不成为“没有这个专家就不能过”的单点故障。

优先“所有人可尝试，专家更快/更稳/代价更小/效果更强”。

## 原型与职业

设计差异时优先提供：

- 不同的行动选择；
- 不同的资源循环；
- 不同的风险偏好；
- 新的 fictional permission；
- 团队协作接口。

少用“同一动作 + 更大数字”作为唯一差异。

## 成长系统

成长可以改变：

- 可解决的问题规模；
- 行动经济；
- 社会/组织权限；
- 可靠性；
- 资源恢复方式；
- 新选择或新后果控制权。

检查“成长跑步机”：如果角色和敌人的数字同比增长，命中率、回合数和决策结构几乎不变，成长可能只是表面升级。

## 长战役适配

需要至少考虑：

- 横向成长 vs 纵向成长；
- 新角色加入的追赶方式；
- 角色死亡/退休/转职；
- 低阶内容是否仍有意义；
- 玩家换构筑是否需要惩罚；
- 能力组合是否产生无限循环或单一最优解。

需要数值预算时调用 `probability-balance-lab`；需要能力模板与批量内容时调用 `rules-content-forge`；需要实测时调用 `playtest-rules-auditor`。
